# Indonesia Infrastructure Atlas

A curated, source-linked atlas of major Indonesian infrastructure, PSN projects
and national programmes. Every record carries a source, a verification date and
an explicit confidence level. The atlas is deliberately **major and curated, not
exhaustive**.

The site is a static, offline build. It works from `file://` and from any local
HTTP server, with no tile server, CDN or remote request.

## What this is, and what it is not

**It is** a static site with six views:

- **Explore:** map, search, filters and a project drawer.
- **Programmes:** the 24 PSN programmes and the eight 2027 PKPN priorities.
- **Corridors:** five Trans corridor summaries with 44 segments.
- **Estates:** 204 industrial estates and SEZs.
- **Companies:** 314 organisations and their sourced project and estate roles.
- **Data:** coverage, charts, methods, sources, downloads and known gaps.

**It is not** a live project tracker, an official government dataset, or a
complete list of Indonesian infrastructure. A row is included only when a source
supports its status.

## Quick start

The generated site is committed, so no build is needed to view it.

```bash
# Option 1: open the language chooser directly
#   site/index.html

# Option 2: serve the site locally
python -m http.server 8765 --directory site
# then open http://localhost:8765/
```

Rebuild and verify:

```bash
python scripts/build_all.py          # validate, rebuild and check the site
python scripts/build_all.py --check  # fail if a rebuild changes a generated byte
```

The optional browser smoke test needs Playwright and Microsoft Edge. Neither is
needed to view or ship the site.

```bash
python scripts/dev/smoke_site.py
python scripts/dev/ux_rehearsal.py
python scripts/dev/check_contrast.py
```

Deep links use hash routes:

```text
site/index.html#/project/tol-solo-yogyakarta-nyia
site/index.html#/explore?sector=road&island=Sumatra
site/index.html#/corridors/trans-java
site/index.html#/data
```

## Build pipeline

`scripts/build_all.py` runs these steps in order:

1. `pipeline/validate.py` — schema, enums, dates, coordinates, foreign keys,
   claims, conflicts and coverage.
2. `pipeline/build_psn_ledger.py` — PSN reconciliation ledger.
3. `pipeline/build_projects.py` — flat project export.
4. `pipeline/build_dictionary.py` — field dictionary.
5. `pipeline/freshness.py` — row-level freshness report.
6. `pipeline/audit_claims.py` — per-fact claim audit.
7. `pipeline/build_i18n.py` — locale payloads and translation coverage.
8. `pipeline/build_site_data.py` — browser payload and downloads.
9. `pipeline/build_locales.py` — English, Indonesian and chooser pages.
10. `pipeline/build_factories_ledger.py` — frozen factory ledger.
11. `pipeline/check_site.py` — payload counts, IDs, search, downloads and
    offline assets.

`--check` hashes all generated files before and after the run and fails if a
rebuild changes a byte. The build never touches git, a remote or a deployment.

See [`scripts/README.md`](scripts/README.md) for every script and importer.

## Data model

`data/curated/` is normalised: one entity or relationship per row, with foreign
keys and one atomic fact per source claim. The full table list, project columns,
status definitions and claim rules are in
[`docs/data-model.md`](docs/data-model.md).

Core tables:

| Table | One row per |
|---|---|
| `projects.csv` | project, with sector, status, location and sourced figures |
| `organizations.csv` | company or agency |
| `project_organizations.csv` | sourced project–organisation role |
| `sources.csv` | source document, snapshot hash and archive path |
| `project_sources.csv` | one atomic project fact and its source |
| `estates.csv` | industrial estate or SEZ |
| `corridors.csv` / `corridor_segments.csv` | Trans corridor and its published sections |
| `psn_register.csv` | official PSN project or programme |
| `programmes.csv` | one of the 24 active PSN programmes |
| `pkpn_programmes.csv` | one of the eight 2027 PKPN priorities |
| `indicators.csv` / `indicator_values.csv` | target and dated observation |
| `translations.csv` | reviewed entity text for the bilingual build |

Status values: `planned`, `under_construction`, `operating`,
`recently_completed`, `stalled`, `unknown`. `unknown` is reserved for
register-only PSN rows where the source does not state implementation status.

Every populated status and numeric fact needs a matching claim. A status change
needs an official source or two independent sources. Disagreements go in
`conflicts.csv` with both values and both sources.

## Adding or updating a record

1. Save the source snapshot to `data/raw/<YYYY-MM-DD>/`; never edit it later.
2. Add a row to `data/curated/sources.csv` with publisher, title, URL, dates,
   type, language, hash and archive path.
3. Add or edit the project in `data/curated/projects.csv`.
4. Add one atomic claim per fact to `data/curated/project_sources.csv`.
5. Add the operator or sponsor to `organizations.csv` and link it in
   `project_organizations.csv`.
6. Set `status_basis` to the evidence, not just the status word.
7. Set `island`, `status_as_of`, `last_verified` and `verification`.
8. Record disagreements in `conflicts.csv`; do not resolve them silently.
9. Add or update the Indonesian display name in `translations.csv` when needed.
10. Run the build and checks:

    ```bash
    python scripts/build_all.py
    python scripts/build_all.py --check
    ```

11. Update `coverage_targets.csv`, `CHANGELOG.md` and any affected doc if
    coverage or behaviour changed.
12. Commit curated rows, rebuilt exports and site data together. Do not push.

Rules for every row:

- No invented status, cost, capacity, target or date.
- Coordinates must be plausible; prefer official or site-specific points.
- A row not re-checked within six months should be treated as unverified.
- No test, placeholder or duplicate entries.
- Use only the status values above.
- Keep `data/exports/`, `site/data/` and `site/downloads/` generated.
- `data/derived/claims_audit.csv` must report no missing claims.

## Languages

The app has one source template and two generated editions:

```text
site/index.html      language chooser
site/en/index.html   <html lang="en">
site/id/index.html   <html lang="id">
```

UI strings live in `data/i18n/ui.en.json` and `data/i18n/ui.id.json`. Entity
translations live in `data/curated/translations.csv`. Programmes carry bilingual
names and summaries; project aliases carry the 88 official Indonesian PSN names.

The build fails if the two catalogues drift or if a programme or corridor loses
a required translation. Numbers, dates and coordinates use `Intl` with `en-GB`
or `id-ID`. The header switch preserves the current view and hash.

Every project has a factual one-sentence summary generated from sourced fields.
It is labelled `AUTO` / `OTOMATIS`; these are not editorial copy. Sourced English
text inside the Indonesian edition carries `lang="en"` and an `EN` tag.

## Caveats and constraints

- **Register-only PSN rows are not implementation records.** 88 projects and 18
  industrial areas carry the official name, number, sector, location and active
  designation only. They stay searchable and downloadable but are excluded from
  the map when the coordinate is a province centroid.
- **Mixed source quality.** Official, secondary and company sources are recorded
  separately. Claims coverage proves that a fact has a source, not that every
  source agrees.
- **Approximate coordinates.** Road rows use BPJT endpoint midpoints or city
  references. Factory points are plant or industrial-park locators, not surveyed
  boundaries.
- **No project geometry.** Projects are points. `project_geometry.csv` exists but
  stays empty until a sourced line or polygon is added.
- **Corridor-level status.** A corridor with one open section and one section
  under construction is `under_construction`; section openings stay in `notes`.
- **Programme targets are mostly blank.** The PSN annex states names and active
  status, not budgets or targets. Do not infer them.
- **The estate map layer is off.** It waits for verified coordinates; the table
  remains complete and downloadable.
- **Freshness is a date check, not live re-verification.** The monthly runbook is
  the real test.
- **The atlas is not a live tracker.** It is refreshed monthly from published
  sources.
- **The release is local only.** Do not create a remote, push, deploy or publish.

## Requirements

- Python 3.10 or newer.
- `pip install -r requirements.txt` for extraction and basemap scripts
  (BeautifulSoup, lxml, Shapely).
- No Node.js or build tooling is needed to view the site.
- Optional: `pip install playwright` and Microsoft Edge for the browser smoke
  test. Playwright is not in `requirements.txt` and is not needed by the build.
